### D-۱) بازبینی مستقل ابزار موازی‌یابِ فاز ۶ (کار دیگری روی همین ریپو)

| `userSchema.phone` را می‌توان به `allowEmpty` برد چون سیاست شماره در `authPolicy.js` است | ✅ **درست** | `database/authPolicy.js:16` `PHONE_PATTERN = /^09\d{9}$/` · `:81-88` `validatePhone` با کدهای `PHONE_REQUIRED`/`PHONE_MALFORMED` · و مسیر ثبت‌نام واقعاً آن را صدا می‌زند: `database/usersStore.js:29` (import) و `:182` (`validatePhone(normalizedPhone)`) ⇒ **گشادکردن Schema هیچ حفره‌ای نساخت** |

**ریشهٔ خطای سوم:** آن فایل با import بدون پسوند نوشته شده
(`export { … } from './articleCatalog'`) که Vite حلش می‌کند ولی Node ESM نه
(`ERR_MODULE_NOT_FOUND`). ابزار فاز ۶ منابع را با `await import(...)` می‌خواند،
پس برای `articles` خطا می‌خورد و دامنه بی‌صدا از فهرست جا افتاد — و در یادداشت
همراهش به‌جای «خوانده نشد» نوشته شد «وجود ندارد».

**اصلاح انجام‌شده:** دامنهٔ `articles` به `scripts/data-sources.mjs` اضافه شد
(`database/content/articles.json` ↔ `src/services/articles/mockData.js` ↔
`articleCatalog.js`) با داوری **`SERVER`** و شاهد خط‌دار:
`articlesService.js:152-154` → `if (!cmsArticles.length) return ARTICLES;` و
`[...cmsArticles, ...ARTICLES.filter((a) => !published.has(a.slug))]` از
`GET /api/public/articles`؛ seed یک‌باره در `contentStore.js:531` (`syncArticles`).
چون فایل با `await import()` قابل خواندن نیست، منبعش صادقانه
**«خوانده‌نشده»** علامت خورد، نه «diff‌شده». نتیجهٔ اجرا:
`دامنه: ۱۰  داوری‌شده: ۷  UNKNOWN: ۳` (پیش‌تر ۹ دامنه بود).

> **درس:** دامنه‌ای که به‌خاطر **خطای خواندن** از یک ابزار جا می‌افتد، به‌عنوان
> «وجود ندارد» ثبت می‌شود. تفاوت «نبود» و «خوانده‌نشد» باید در خروجی ابزار
> صریح باشد، وگرنه ابزار خودش منبع نادرستی می‌سازد.

### D-۲) تکمیل ابزار: بارگذارِ سه‌حالته + diff‌های واقعیِ انجام‌نشده

در جریان رفع بالا معلوم شد مشکل فقط `articles` نبود: **۷ دامنه** با برچسب
`rows: null` رها شده بودند که در واقع **آرایهٔ رکورد** دارند — یعنی diffی که
کل هدف این ابزار است، برایشان هرگز اجرا نشده بود.

الگوی `try { await import(p) } catch {}` این شکست را **بی‌صدا** می‌بلعید و
همه‌چیز زیر یک برچسب مبهم («ثابت‌های UI / خوانده‌نشده») می‌رفت.

**اصلاح انجام‌شده در `scripts/data-sources.mjs`:**

1. **بارگذارِ سه‌حالتهٔ `loadStatic()`** با برچسب صریح در خروجی:

   (`--loader:.png=empty` و…)، چون محتوای تصویر در diff بی‌اثر است.
2. **رکوردهای واقعی** جای `rows: null` آمد: `wiki/WIKI_ENTITIES` ·

   `articles/ARTICLE_CATALOG`+`ARTICLES`.
3. **diff کلیدی** برای `flashcards` · `international` · `references` · `articles`

4. `note` صریح برای منابعی که واقعاً رکورد ندارند (`notes` = فقط ثابت‌های UI ·
   `league` = بستهٔ دموی ۲۴-export) — دیگر با «خوانده‌نشده» قاطی نمی‌شوند.

### F-۲) مُهر زمانی — دو استثنای مستند

| نوع | فیلدها | قالب |
|---|---|---|
| `timestamp()` | اکثریت قاطع | ISO 8601 رشته |
| `epoch()` | `feedback.createdAt` · `feedbackReply.createdAt` · نشست کاربر (`createdAt`/`expiresAt`/`lastSeenAt`) | عدد صحیح میلی‌ثانیه |

> `timestamp()` رشتهٔ خالی را در نرمال‌سازی به `null` می‌برد («تعیین‌نشده»).

### F-۳) نرمال‌سازی (≠ تعمیر — بند ۵۳)

| تابع | تبدیل | تعمیر؟ |
|---|---|---|
| `normalizeDigits` | `۰۱۲۳` → `0123` | ❌ تبدیل بازنمایی |
| `normalizePhone` | ارقام فارسی، حذف فاصله/خط تیره، `+98`/`0098` → `0` | ❌ |
| `normalizeWhitespace` | نویسهٔ کنترلی، فاصلهٔ تکراری، trim | ❌ |
| `normalizeSlug` / `normalizeTag` / `normalizeEmail` | شکل متعارف | ❌ |
| `normalizeStringArray` | trim، حذف خالی، یکتاسازی با حفظ ترتیب | ❌ |
| `normalizeRecord` | فرود **بازگشتی** به آبجکت و آرایهٔ آبجکت | ❌ |
| «abc» → 0 | — | **ممنوع** |

> **یافتهٔ F-۳-۱ — نرمال‌سازی فقط سطح اول بود.**
> `normalizeRecord` قبلاً فقط فیلدهای سطح اول را می‌دید، پس `profile.term = "۸"`
> هرگز نرمال نمی‌شد. **اصلاح شد**: فرود بازگشتی به `object` با `fields`،
> نگاشت آزاد با `item`، و آرایهٔ آبجکت. (`json()` عمداً فرود نمی‌کند — قراردادش آزاد است.)
> مسیر برگ تغییرها اکنون نقطه‌ای گزارش می‌شود (`profile.term`, `rows[0].code`).

> **یافتهٔ F-۳-۲ — شمارش نرمال‌سازی دروغ می‌گفت (۶۴۴ در برابر ۷ واقعی).**
> `normalizeStringArray` همیشه یک آرایهٔ **تازه** می‌ساخت، پس مقایسهٔ `!==` هر
> آرایهٔ سالم را «تغییرکرده» می‌شمرد. نتیجه: `normalizedFields: 644` که ۶۳۷ موردش
> کاذب بود. **اصلاح شد** با (الف) بازگرداندن **همان ارجاع** وقتی خروجی عیناً
> برابر ورودی است، و (ب) مقایسهٔ **ساختاری** (`sameValue`) به‌جای ارجاعی.
> عدد واقعی: **۷** فیلد (۵ `mediaTag.color` و ۱ `banner.startDate` و ۱ `banner.endDate` — همه `""` → `null`).
> این مهم است چون `data:repair` بر همین diff بنا شده؛ عدد بادکرده یعنی نوشتن بی‌دلیل.

> **یافتهٔ F-۳-۳ — کد مرده.** `.replace(/\u200c/g, '\u200c')` در `normalizeWhitespace`
> نیم‌فاصله را با نیم‌فاصله عوض می‌کرد (no-op). **حذف شد.** اثبات بی‌اثری: اسکن
> هر ۴۳ فایل نشان داد هیچ `\u200b`/`\ufeff`/`\u00ad`/`\u200d`/`\u00a0` در داده نیست؛
> تنها نویسهٔ غیرلاتین، **یک** رقم فارسی در `users.json` است.

### F-۴) Slug

`normalizeSlug` + `ensureUniqueSlug` سمت `contentStore`؛ در Schema به‌صورت
`slug()` با الگوی `^[a-z0-9]+(?:-[a-z0-9]+)*$` مدل شده. یکتایی در سطح مجموعه.

## G. اعتبارسنجی

### G-۱) چهار حالت

| حالت | کاربرد | فیلد الزامی غایب | فیلد ناشناخته | فیلد محافظت‌شده | تغییرناپذیر | Default |

> کلید اضافه می‌تواند به ارتقای اختیار یا دستکاری آمار منتهی شود.

### G-۲) ورودی ≠ ذخیره‌شده (بند ۳۰ و ۳۲)

- `id`, `createdAt`, `updatedAt`, `publishedAt`, `createdBy`, `updatedBy`, `role`,
  `permissions`, `isSuperAdmin`, `score`, `views`, `likes`, `stats` و همهٔ
  `*Token`/`*Secret`/`*Hash` در `SYSTEM_PROTECTED_FIELDS` هستند.
- در `create`/`update` هر فیلد محافظت‌شده ⇒ `protected_field`.
- **مجوز از کلاینت هرگز پذیرفته نمی‌شود** (قرار فاز ۳): `role`/`permissions`
  ارسالی بی‌اثر است؛ نقش فقط server-side اعمال می‌شود.

### G-۳) قرارداد خطا — بدون تغییر (بند ۵۴)

```
{ success: false, error: { code, message, fields? } }
```
`STATUS_BY_CODE` دست‌نخورده: `VALIDATION_ERROR:400` · `FORBIDDEN:403` ·
`NOT_FOUND:404` · `CONFLICT:409` · `PAYLOAD_TOO_LARGE:413` · `RATE_LIMITED:429` ·
`INTERNAL_ERROR:500` + شش کد `PUBLISH_*`.
`toErrorFields(result)` همان `{ field: code }` را می‌سازد که `adminApi.fail` می‌پذیرد.

### G-۴) اعتبارسنجی عددی/آرایه/آبجکت

`num` گارد `NaN` و `Infinity` دارد (`not_finite`) — مهم چون `NaN` در JSON به
`null` تبدیل می‌شود و «عدد نامعتبر» بی‌صدا به «غایب» تبدیل می‌شد.
`arr` فقط آرایه‌بودن/طول/یکتایی را می‌سنجد و **اعضا را بازگشت نمی‌زند**
(اعتبارسنجی اعضا کار `validator.collectField` است؛ بازگشت دوطرفه خطاهای تکراری می‌ساخت).

| تبدیل نوع (`String()`/`Array.isArray`/`bool()`/`num()`) | ۱۱۳ |

| پاک‌سازی (`sanitize`/`normalize*`/`trim`) | ۱۱۰ |
| فهرست مجاز (`includes`/`_STATUSES`/`_KINDS`/`_EXTENSIONS`) | ۱۰۴ |
| گارد عددی (`Number.isFinite`/`Number()`/`parseInt`) | ۱۰۴ |
| رد صریح (کد خطای اعتبارسنجی یا `fail('متن')`) | ۷۰ |
| **لایهٔ Schema (`validateRecord`/`assertValid`)** | **۰** |

### K-۲) یافتهٔ اصلی §۴۶

> **لایهٔ Schema وجود دارد ولی هیچ Endpointای از آن استفاده نمی‌کند.**
> ۱۸۵ مسیر، صفر ارجاع به `validateRecord`/`assertValid`. اعتبارسنجی امروز در
> ۷۸٪ مسیرهای نوشتن **در لایهٔ ذخیره‌سازی** انجام می‌شود (کد موجود و کارآمد).
> این **باگ نیست** — بندهای «بدون بازنویسی API» و «بدون تغییر معنایی» مانع
> سیم‌کشی اجباری بودند. ولی یعنی:
> ۱) Schema امروز **ابزار بازرسی** است، نه نگهبان زمان اجرا؛
> ۲) هر مسیر تازه باید صریح تصمیم بگیرد کدام لایه اعتبارسنجی کند؛
> ۳) مسیر «ارتقای تدریجی» آماده است: `assertValid(schema, ctx.body, {mode:'create'})`
>    را می‌توان بدون تغییر قرارداد خطا به هر هندلر اضافه کرد.

**قید صداقتی:** «۰ مسیر بدون سیگنال» شرط **لازم** است، نه کافی. واژگان سیگنال
عمداً گسترده است (`.slice(0, n)` و `trim(` هر جایی match می‌شوند)؛ پس این عدد
می‌گوید «هر مسیر نوشتن دست‌کم یک مکانیزم برخورد با ورودی دارد»، نه
«هر مسیر ورودی را کامل اعتبارسنجی می‌کند». سنجهٔ سختِ باقی‌مانده همان
**۰ از ۱۱۷ در لایهٔ Schema** است.

### K-۳) ۱۴ موردِ گزارش‌شده، منفی کاذبِ ابزار بودند

بازبینی دستی هر ۱۴ مسیر (هندلر در `database/adminApi.js` + تابع ذخیره در
`mediaStore.js`/`contentStore.js`/`publishingStore.js`) نشان داد همه‌شان
اعتبارسنجی دارند. ریشهٔ خطا **دو باگ در ابزار ممیزی** بود:

**باگ ۱ — واژگان سیگنال، گاردهای دست‌نویس را نمی‌دید.**
`mediaStore.js` یک کمک‌تابع گارد دارد: `function fail(message, code = 'VALIDATION_ERROR')`.
رشتهٔ `VALIDATION_ERROR` در **امضای** تابع است، نه در بدنهٔ فراخوانی
(`fail('متن پاسخ الزامی است')`). سیگنال قدیمی فقط `/VALIDATION_ERROR/` را در بدنه
می‌گشت ⇒ هر ۴۹ گارد `fail()` در `mediaStore.js` دیده نمی‌شد.
همین‌طور `trim(value, max)` (کمک‌تابع محلی) با الگوی `.trim()` (متد) و
`bool()`/`num()` با الگوی `String()`/`Boolean()` فرق داشتند، و `.slice(0, max)`
به‌عنوان گارد طول شمرده نمی‌شد.

**باگ ۲ — `functionBody` آکولادِ پارامترِ تخریبی را بدنه می‌گرفت.**
```js
const braceStart = text.indexOf('{', hit.index);   // ❌
```
برای `export function replyInboxItem(id, { text, admin = null } = {}) {` اولین
`{` همان الگوی تخریب **پارامتر** است؛ پس «بدنه» می‌شد `{ text, admin = null }`
و هیچ سیگنالی داخلش نبود. **هر تابعی که پارامتر تخریبی داشت کاذب «بدون
اعتبارسنجی» می‌شد** — یعنی `approveContent`، `scheduleContent`،
`publishContent`، `createMedia`، `setAccountCredentials`، `updateAsset`،
`setNotificationState`. رفع با `bodyBraceIndex()` که تا عمق پرانتز صفر نشود
آکولاد نمی‌شمارد.

**دو اصلاح جانبی:**
- `POST .../preview` (سه مسیر) «نوشتن» شمرده می‌شد در حالی که فقط محاسبه است و
  چیزی ذخیره نمی‌کند ⇒ لایهٔ تازهٔ `preview`.
- سیگنال `reject` نباید `fail('NOT_FOUND', '...')` را اعتبارسنجی بشمارد —
  آن **پاسخ خطا** است، نه بررسی ورودی. پس فقط تک‌آرگومانی `fail('متن')`
  (سبک `mediaStore.js`) یا کد خطای صریحِ اعتبارسنجی سیگنال است.

**خودآزمون:** `npm run audit:api:selftest` سه سنجه دارد که همین دو کلاس باگ را
می‌گیرد (تابع با پارامتر تخریبی، تابع ساده، arrow بدون بلوک، و تمایز
`fail('متن')` از `fail('NOT_FOUND', ...)`). اسکریپت خودش هم در هر اجرا
خودآزمون را می‌دواند و در صورت شکست `exitCode=1` می‌دهد — تا نتیجهٔ ممیزی
دیگر بی‌صدا غلط نشود.

#### M-۴-۱) دو حادثهٔ واقعی از همین هم‌زمانی (۳۰ سپتامبر)

**الف) شکست بی‌صدای `find -newermt` — نتیجهٔ غلط «نویسنده متوقف شده».**

قاعدهٔ کلی: روی این مک «خروجی خالی» را بدون دیدن stderr و کد خروج، مدرک «اتفاقی نیفتاد» نگیر.
