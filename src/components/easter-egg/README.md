# ایستر اگ — مینی‌گیم پیکسلی تپش

> ۵ کلیکِ پشت‌سرهم روی نشانِ تپش در هر هدری ⇒ یک شوترِ فضاییِ پیکسلیِ تمام‌صفحه.
> کاربرِ عادی هیچ نشانی از آن نمی‌بیند؛ هیچ متن، tooltip یا راهنمایی وجود ندارد.

## ۱. فایل‌های ایجادشده

| فایل | نقش |
| --- | --- |
| `egBus.js` | اتوبوسِ رویدادِ سراسری (`triggerEasterEgg` / `onEasterEggTrigger`) |
| `egStorage.js` | ذخیره‌سازی در namespace اختصاصی `tapesh:easterEgg:*` |
| `egAudio.js` | جلوه‌های صوتیِ سنتز‌شده با Web Audio (هیچ فایل صوتی‌ای در پروژه نیست) |
| `egCollision.js` | برخوردِ AABB و کمکی‌های عددی |
| `sprites.js` | اسپرایتِ فشردهٔ باس + `decode` |
| `pixelGameEngine.js` | موتورِ بازی (کلاسِ مستقل از React، گامِ ثابت، canvas) |
| `TapeshPixelGame.jsx` | پوستهٔ React: HUD، کنترل لمسی، صفحهٔ پایان |
| `TapeshEasterEgg.jsx` | پوستهٔ overlay: پورتال، Escape، قفلِ اسکرول، دکمهٔ صدا/خروج |
| `easterEgg.css` | استایل، کاملاً زیر `.eg-*` و `.brand.is-egg-*` |
| `pixelArts.js` | (از قبل بود) اسپرایت‌های بازیکن/دشمن/پاورآپ — پالتش همان پالتِ تپش است |

## ۲. فایل‌های تغییر‌یافته

| فایل | تغییر |
| --- | --- |
| `src/hooks/useEasterEggClick.js` | بازنویسی: شمارش در `ref` (بدون stateِ کهنه)، ریستِ زمانی، cleanup کامل، `enabled`، بدون `preventDefault` |
| `src/App.jsx` | `Brand` حالا خودش شمارنده دارد و رویداد را منتشر می‌کند؛ نشانِ فوتر `interactive={false}`؛ ریشهٔ اپ به `TapeshApp` تبدیل شد که `<App />` + `<TapeshEasterEgg />` را رندر می‌کند |
| `src/layout/dashboard/Brand.jsx` | همان منطق برای هدرِ داشبورد (بدون prop-drilling) |

**هیچ خطی از routing، stateِ داشبورد، auth، توکن‌های CSS یا `styles.css` دست نخورد.**

## ۳. فعال‌سازی

- هر `Brand` (هدرِ صفحهٔ اصلی + هدرِ داشبورد) از `useEasterEggClick` استفاده می‌کند.
- ۵ کلیک با فاصلهٔ کمتر از **۱۵۰۰ms** ⇒ `triggerEasterEgg()` روی `window` یک `CustomEvent` می‌فرستد.
- `TapeshEasterEgg` (یک بار در ریشه) آن را می‌شنود، یک `runId` تازه می‌سازد و overlay را باز می‌کند.
- بازخوردِ نامحسوس: از کلیک چهارم نشان هالهٔ طلایی می‌گیرد و در کلیک پنجم انیمیشنِ `eg-brand-burst` می‌زند. هیچ شمارنده یا پیامی نمایش داده نمی‌شود.
- هیچ listener دوگانه‌ای ساخته نمی‌شود: منطق در یک hook است و هر هدر یک نمونهٔ مستقل دارد.

## ۴. رندر

- **Canvas** با رزولوشنِ منطقیِ `320×560` و `image-rendering: pixelated`.
- اسپرایت‌ها یک بار روی canvasِ آفلاین کش می‌شوند؛ در حلقه فقط `drawImage` است.
- مقیاسِ نمایش **صحیح (integer)** است تا پیکسل‌ها تار نشوند؛ در صفحه‌های کوچک کسری می‌شود.
- حلقه: `requestAnimationFrame` + انبارهٔ گامِ ثابت `1/60` ⇒ سرعتِ بازی مستقل از نرخِ نمایشگر. `setInterval` صفر.
- HUD در DOM است (فونت و ارقامِ فارسی) و با نرخِ ~۱۰Hz به‌روز می‌شود، نه هر فریم.

## ۵. کنترل‌ها

| بستر | حرکت | شلیک | خروج |
| --- | --- | --- | --- |
| دسکتاپ | `←/→` و `A/D` | `Space` (یا `W/J/↑`) | `Esc` یا دکمهٔ ✕ |
| موبایل | دکمه‌های ◀ ▶ یا کشیدنِ انگشت روی صفحه | دکمهٔ `FIRE` (یا کشیدن = حرکت + شلیکِ خودکار) | دکمهٔ ✕ همیشه در نوارِ بالا |

- `preventDefault` فقط روی کلیدهای خودِ بازی؛ اگر تمرکز روی دکمه‌ای باشد، بازی کنار می‌کشد تا Space همان دکمه را فعال کند.
- کنترل‌های لمسی روی دستگاه‌های `pointer: fine` پنهان می‌شوند.

## ۶. امتیاز و رکورد

- کلیدها: `tapesh:easterEgg:highScore` و `tapesh:easterEgg:muted` (هیچ کلید دیگری نوشته نمی‌شود).
- همهٔ دسترسی‌ها در `try/catch`؛ در حالتِ خصوصی/بدون localStorage بازی سالم می‌ماند.
- صفحهٔ پایان: امتیاز، موج، رکورد + نشانِ چشمک‌زنِ `NEW HIGH SCORE!` + `PLAY AGAIN` / `EXIT`.

## ۷. پایانِ کار = صفر پردازش

- بستنِ overlay ⇒ `TapeshPixelGame` unmount می‌شود ⇒ `engine.destroy()`:
  `cancelAnimationFrame`، حذفِ listenerهای keydown/keyup/blur/visibilitychange، `sfx.dispose()`.
- پوسته وقتی بسته است `null` برمی‌گرداند ⇒ هیچ گره‌ای در DOM نیست.
- رها کردنِ تب ⇒ `visibilitychange` بازی را pause می‌کند (بدون پرشِ dt).
- سقفِ ذرات (۳۴۰) و پاک‌سازیِ موجودیت‌های خارج از صفحه ⇒ بدون نشتیِ حافظه.

## ۸. تعادلِ بازی

- موج‌های ۱ و ۲: دشمنِ ساده/سرعتِ کم. موج ۳+: حرکتِ سینوسی. موج ۴+: زیگزاگ و ترکیبِ همهٔ نوع‌ها + شلیکِ دشمن.
- هر **۳** موج: باس («کتابِ امتحانیِ عصبی») با دو الگوی شلیک، نوارِ جان و ریزشِ پاورآپ.
- پاورآپ‌ها: شلیک سریع، شلیک دوگانه، سپر، موج انفجاری.
- افکت‌ها: screen shake، ذراتِ انفجار، فلاشِ ضربه، پاپ‌آپِ امتیاز، بنرِ موج، صدا.

## ۹. تست‌های انجام‌شده (بدون مرورگر)

موتور با یک stubِ canvas/`document`/`window` و باندلِ ESM با esbuild در Node اجرا شد:

- ۲٬۵۰۰ فریم بازی بدون خطا؛ مرگ، ثبتِ رکورد، `restart` تمیز و `destroy` بی‌نشتی.
- ۳۰٬۰۰۰ فریمِ دوم: باس در موج ۳ ساخته و نابود شد، موج به ۵ رسید، هر چهار پاورآپ اعمال شد، سقفِ ذرات و shake رعایت شد.
- باندلِ کاملِ `App.jsx` با esbuild بی‌خطا (فقط هشدارهای از پیش موجودِ `import.meta`).
- **تستِ رابطِ کاربری عمداً انجام نشد** (طبق درخواست).

## ۱۰. نکات و trade-off

- **دو فایلِ نیمه‌کارهٔ قبلی باقی مانده‌اند**: `GameEngine.js` و `GameEngine.jsx` (نسخهٔ ناتمامِ پیشین؛ هیچ‌جا import نمی‌شوند). برای حذف، تأیید لازم است.
- مقیاسِ صحیح یعنی روی دسکتاپ قابِ بازی حدوداً `320×560` می‌ماند؛ بزرگ‌تر کردنش پیکسل‌ها را نامنظم می‌کرد.
- `sfx.dispose()` در هر بستن، بافتِ صدا را می‌بندد؛ باز شدنِ بعدی بافتِ تازه می‌سازد. با «فعال‌سازی چسبندهٔ» مرورگر بی‌مشکل پخش می‌شود.
- هیچ asset، نام، موسیقی یا کدِ دارای copyright وارد نشد؛ تمام صداها سنتز و تمام اسپرایت‌ها درونِ پروژه ساخته شده‌اند.
