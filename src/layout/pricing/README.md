# لایهٔ تعرفه‌ها — `#pricing`

> صفحهٔ مستقل تعرفه‌ها. مسیرش روی hash است و از هدر سایت باز می‌شود
> (لینک «تعرفه‌ها»). داده و محاسبه‌ها در `src/services/pricing/pricingService.js`
> هستند؛ این پوشه فقط رندر می‌کند.

## چرا لایهٔ جدا و نه یک بخش در صفحهٔ اصلی

تعرفه یک «تصمیم» است، نه یک بلوک تبلیغاتی. جدا کردنش سه چیز می‌دهد:
لینک‌پذیری مستقل، امکان معرفی محصول پیش از قیمت، و فضای کافی برای مقایسهٔ
قابلیت‌ها. صفحهٔ اصلی فقط لینک می‌دهد.

## مدل داده (`pricingService.js`)

- `PRICING_PLANS` — عادی، پرو (پیشنهادی)، گروهی. هر پلن: `monthlyAmount`،
  `features`، `accent`، `recommended`، و برای گروهی `seats` با تخفیف پله‌ای.
- `BILLING_CYCLES` — ماهانه (۰٪)، سه‌ماهه (۱۰٪)، سالانه (۲۰٪).
- `CAPABILITY_ROWS` — ۱۰ قابلیت با `coverage` هر پلن: `full | partial | none`.
- `PRICING_PRODUCTS` — چهار محصول معرفی‌شده پیش از تعرفه.
- `PAYMENT_STATUS` — وضعیت درگاه پرداخت (فعلاً «در حال اتصال»).
- توابع خالص: `quote()`، `discountPercentFor()`، `clampSeats()`، `coverageOf()`،
  `formatToman()` / `formatNumberFa()` / `formatPercentFa()` / `toFa()`.

**قاعده:** هیچ عدد یا درصدی در UI نوشته نمی‌شود. اضافه‌کردن پلن، تغییر قیمت یا
تغییر تخفیف فقط ویرایش همین فایل است؛ UI خودش را تطبیق می‌دهد.

### ⚠️ مبالغ نمونه‌اند

`PRICING_META.amountsConfirmed` روی `false` است و `PRICING_META.note` توضیح
می‌دهد. تا وقتی مالک محصول مبالغ واقعی را در `PRICING_AMOUNTS` نگذارد و پرچم را
`true` نکند، یک یادداشت شفاف پای صفحه می‌ماند (`.pr-footnote`) و هیچ مبلغی
«قطعی» جا زده نمی‌شود. تخفیف گروهی هم عمداً روی تخفیف دوره سوار نمی‌شود تا وعدهٔ
اشتباه ساخته نشود.

## تعامل‌ها و حرکت‌ها

| تعامل | پیاده‌سازی |
|---|---|
| ردیابی اشاره‌گر روی کارت | `useSurfacePointer` → `--pr-mx/--pr-my` (نور) و `--pr-tilt-x/--pr-tilt-y` (تیلت حداکثر ۱٫۱ درجه). با `requestAnimationFrame` گِرد می‌شود؛ هیچ state ری‌اکتی در مسیر حرکت ماوس نیست. |
| تغییر قیمت | `AnimatedNumber` با easeOutCubic؛ اگر وسط انیمیشن مقدار عوض شود، از همان نقطه ادامه می‌دهد |
| هاور کارت | بالا آمدن، تغییر سایه، روشن‌شدن لبه، و هایلایت پله‌ای امکانات با `transition-delay: calc(var(--pr-i) * 24ms)` |
| انتخاب پلن | `is-selected` روی کارت + به‌روزرسانی هم‌زمان بلوک مالی، ماتریس و فراخوان پایانی |
| هاور سرستون ماتریس | همان ستون در کل جدول روشن می‌شود (state محلی خود ماتریس) |
| ورود معرفی محصولات | کلاس `is-visible` روی بخش (مکانیزم `data-reveal` سایت) → کشیده‌شدن ریل، بالا آمدن ردیف‌ها، «کشیده‌شدن» نشانهٔ گرافیکی با `pathLength="1"` + `stroke-dashoffset`، و نشستن چیپ‌ها |
| CTA | هالهٔ لغزان ظریف (`::after`)، جابه‌جایی ۴ پیکسلی آیکون؛ کارت پیشنهادی از ابتدا پُررنگ است |

**قاعدهٔ تأخیر:** `transition-delay` فقط به ویژگی‌های ورود (`opacity`/`transform`)
داده می‌شود، نه به `border`/`color` — وگرنه هاور هم با همان تأخیر کند می‌شود.
برای همین در این فایل چند جا `transition-property` + `transition-duration` +
`transition-delay` جدا نوشته شده است، نه `transition` کوتاه.

## واکنش‌گرایی

- **دسکتاپ:** سه کارت کنار هم؛ ماتریس به‌شکل جدول تحریریه.
- **≤۱۰۸۰px:** دو ستون؛ کارت سوم تمام‌عرض.
- **≤۹۰۰px:** ماتریس به «تک‌کارتی متمرکز» با تب تبدیل می‌شود (ترکیب‌بندی نو، نه
  فقط زیر هم چیدن)؛ پنل مالی یک‌ستونه.
- **≤۶۴۰px:** کارت‌ها یک‌ستونه، نشانهٔ گرافیکی محصولات حذف می‌شود و ردیف به
  «شماره + متن» می‌رسد.

## دسترس‌پذیری

- کنترلر دوره: `role="radiogroup"` + `role="radio"` + `aria-checked` + کلیدهای
  چپ/راست (در RTL: چپ = گزینهٔ بعدی) و Home/End.
- ماتریس موبایل: تب‌های واقعی `tablist/tabpanel` با `aria-selected` و `hidden`.
- ماتریس دسکتاپ: `<table>` بومی با `caption` پنهان و `th scope`.
- هر دکمهٔ انتخاب پلن `aria-pressed` دارد؛ قیمت‌ها در `aria-live` نیستند (چون با
  کلیک کاربر عوض می‌شوند، نه خودکار).
- همهٔ حرکت‌ها گارد `prefers-reduced-motion` دارند — و در آن حالت محتوای معرفی
  محصول از ابتدا در حالت نهایی دیده می‌شود (پنهان نمی‌ماند).

## بررسی

```bash
npm run theme:check     # شامل ۲۸ سنجهٔ لایهٔ تعرفه در verify-render
```

سنجه‌ها هم منطق خالص (`quote`, تخفیف پله‌ای, سقف نفرات, قالب‌بندی فارسی) و هم
رندر سرور (ترتیب محصول→تعرفه، تعداد کارت‌ها، تب‌ها، `aria-pressed`، حضور یادداشت
شفافیت) را پوشش می‌دهند. برای تأیید بصری، `agent-browser` با اسکرین‌شات دسکتاپ و
موبایل و هر دو تم استفاده شده است.

## نکات نگهداری

- لنگرهای داخلی لایه (`#pr-products`, `#pr-plans`, `#pr-compare`) در `App.jsx`
  داخل مجموعهٔ صریح `PRICING_HASHES` ثبت شده‌اند. **هر لنگر تازه باید آن‌جا اضافه
  شود**، وگرنه با یک کلیک کاربر از لایه بیرون می‌افتد. حدس پیشوندی نزن.
- اسکرول به بالای صفحه فقط «هنگام ورود» به لایه اجرا می‌شود (مقایسهٔ مسیر قبلی و
  فعلی در `syncAuthRoute`)، وگرنه پرش لنگر داخلی را می‌خورد.
- کلاس‌ها همه `pr-` هستند. توکن‌های محلی (`--pr-*`) به توکن‌های جهانی ارجاع
  می‌دهند، پس هر دو تم بدون پاس جداگانه درست می‌مانند.
- اگر پلن یا قابلیت تازه اضافه شد، هم `pricingService.js` و هم جدول این فایل را
  به‌روز کن؛ بعد `npm run theme:check` بزن.
