# مرکز تحلیل تپش (Analytics Center)

مرکز فرمان داده‌محور پنل مدیریت: ۱۶ بخش، از ترافیک و آموزش تا امنیت و درآمد.
آدرس: `/#admin/analytics` (هر بخش آدرس خودش را دارد، مثلاً `/#admin/analytics/traffic`)

---

## ۱. اصل بنیادی: هیچ عدد ساختگی

این تنها قاعده‌ای است که کل این لایه حول آن ساخته شده:

> **هر عددی که در این پنل دیده می‌شود، از یک منبع واقعی آمده است. اگر منبعی وصل
> نباشد، پنل به‌جای عدد تخمینی یا نمودار تزئینی، صریحاً می‌گوید «نیازمند اتصال»
> و نام متغیرهای محیطی لازم را نشان می‌دهد.**

پیاده‌سازی این قاعده در سه جا دیده می‌شود:

| جا | رفتار |
|---|---|
| سنجهٔ بدون مقدار | به‌جای `0`، علامت `—` و دلیل نبودنش نمایش داده می‌شود |
| بخش بدون منبع | کامپوننت `NeedsConnection` با نام دقیق متغیرهای محیطی |
| بازهٔ بدون رویداد | نمودارها حالت خالی نشان می‌دهند، نه محور خالی با خط صاف |

منابع دادهٔ واقعی که همین امروز کار می‌کنند:

| منبع | چه چیزی می‌دهد |
|---|---|
| تلمتری مرورگر (Beacon) | بازدید صفحه، نشست، دستگاه، مرورگر، منبع ورود، UTM، Core Web Vitals، خطای جاوااسکریپت |
| `database/users.json` | کاربران، پروفایل، مبدأ آشنایی، جمعیت‌شناسی |
| `database/content/*.json` | مقاله، صفحه، رسانه، بنر و وضعیت انتشارشان |
| `database/content/activity.json` | گزارش رویدادهای پنل (چه کسی چه تغییری داد) |
| سنجه‌های درخواست HTTP | زمان پاسخ، نرخ خطا، توزیع کد وضعیت، کندترین مسیرها |
| `node:os` و `node:fs` | پردازنده، حافظه، دیسک، حجم پایگاه داده |
| ماژول‌های محصول پروژه | ۴۷ سؤال، ۴۶۶ مدخل ویکی، ۵۳ فلش‌کارت، ۵۶ گره دانش، ۵ آزمون بین‌الملل، ۶ آزمون هماهنگ، ۱۷ ماژول درسنامه |

```

        │  مرورگر کاربران سایت (src/App.jsx)                  │
        │  trafficTracker.js — page_view، session، CWV، error  │
        └───────────────────────┬─────────────────────────────┘
                                │ POST /api/public/analytics/collect
                                ▼
        ┌─────────────────────────────────────────────────────┐
        │  database/analyticsStore.js                         │
        │  ذخیره‌سازی رویداد + سنجهٔ درخواست + منابع سیستم     │
        │  → database/content/events.json                     │
        └───────────────────────┬─────────────────────────────┘
                                │
                                ▼
        ┌─────────────────────────────────────────────────────┐
        │  analyticsEngine.js   (بخش ۱–۱۰)                    │
        │  analyticsInsights.js (بخش ۱۱–۱۶)                   │
        │  محاسبهٔ واقعی: سشن‌سازی، Cohort، قیف، رگرسیون، Z     │
        └───────────────────────┬─────────────────────────────┘
                                │  database/adminApi.js
                                │  GET /api/admin/analytics/<section>
                                ▼
        ┌─────────────────────────────────────────────────────┐
        │  src/layout/admin/analytics/**                      │
        │  AnalyticsCenter.jsx + ۱۶ بخش + کیت نمودار          │
        └─────────────────────────────────────────────────────┘
```

**تفکیک لایه‌ها (همان الگوی بقیهٔ پروژه):**

| لایه | فایل | مسئولیت |
|---|---|---|
| داده | `analyticsStore.js` | فقط ذخیره/خواندن و سنجه‌های خام. هیچ محاسبهٔ تحلیلی نمی‌کند. |
| محاسبه | `analyticsEngine.js` + `analyticsInsights.js` | تجمیع، سشن‌سازی، مقایسهٔ بازه‌ها، تحلیل. هیچ‌کدام UI نمی‌شناسند. |
| API | `database/adminApi.js` | مسیرها، مجوزها، اعتبارسنجی. |
| UI | `src/layout/admin/analytics/**` | نمایش. هیچ‌کدام مستقیم `fetch` نمی‌زنند. |

نتیجه: اتصال به یک دیتابیس واقعی یا Google Analytics فقط بدنهٔ توابع لایهٔ داده را
عوض می‌کند — نه موتور محاسبه، نه API، نه UI.

### سئو — بازرسی واقعی، نه دادهٔ ساختگی

بخش سئو روی محتوای واقعی CMS یک **بازرسی درون‌صفحه‌ای** انجام می‌دهد:

- نبود یا تکراری بودن عنوان متا
- نبود توضیح متا یا طول نامناسب آن
- محتوای کم‌متن (زیر آستانهٔ کلمه)
- نبود لینک داخلی
- نبود متن جانشین تصویر
- محتوای کهنه (بیش از ۶ ماه ویرایش نشده)
- `noindex` و نبود canonical

خروجی یک **SEO Health Score** واقعی است. در مقابل، «کلیک»، «نمایش»، «CTR» و
«رتبهٔ کلمات کلیدی» فقط از Google Search Console می‌آید و تا اتصال آن، بخش با
حالت «نیازمند اتصال» نمایش داده می‌شود.

## ۵. تحلیلگر هوشمند

موتور تحلیل **آماری و قاعده‌محور** است، نه فراخوانی یک مدل زبانی. هر ادعا با یک
محاسبهٔ قابل بازتولید پشتیبانی می‌شود:

| قابلیت | روش پیاده‌سازی |
|---|---|
| تشخیص روند | رگرسیون خطی کمترین مربعات روی سری روزانه + ضریب تعیین R² برای «قدرت روند» |
| تشخیص ناهنجاری | امتیاز Z روی پنجرهٔ لغزان؛ `|Z| > 2` = ناهنجاری، علامت آن = جهش یا افت |
| ریشه‌یابی | تفاضل نیمهٔ اول و دوم بازه در سطح منبع، صفحه و نرخ خطا |
| پیش‌بینی | ادامهٔ خط رگرسیون با فاصلهٔ اطمینان از انحراف معیار باقی‌مانده‌ها |
| اولویت‌بندی | هر یافته به `critical / high / medium / low` نگاشت می‌شود |

هر یافته دقیقاً این ساختار را دارد — همان چیزی که برای اقدام لازم است:

```
عنوان · شدت · گزاره · شواهد عددی · علت احتمالی · اثر · اقدام پیشنهادی · درجهٔ اطمینان
```

اگر `LLM_API_KEY` تنظیم شود، یک **روایت متنی طبیعی** به همین یافته‌ها اضافه می‌شود —
اما تحلیل پایه بدون آن هم کامل کار می‌کند. این تصمیم عمدی است: تحلیل نباید به یک
سرویس بیرونی وابسته باشد تا کار کند.

## ۶. مجوزها (RBAC)

هر بخش یک Permission مستقل دارد تا دادهٔ حساس به نقش غیرمجاز نرسد:

| Permission | بخش‌ها |
|---|---|
| `analytics.read` | نمای کلی، ترافیک، آموزش، عملکرد، محصولات، محتوا، بازاریابی، سیستم، خطاها، لحظه‌ای، هشدارها، تحلیلگر |
| `analytics.users.read` | کاربران (شامل فهرست کاربران) |
| `analytics.seo.read` | سئو |
| `analytics.security.read` | امنیت (ورود ناموفق، IP، گزارش رویداد) |
| `analytics.revenue.read` | درآمد |
| `analytics.alerts.manage` | ساخت/ویرایش/حذف هشدار، پاک‌سازی رویدادها |
| `analytics.export` | خروجی CSV / Excel / PDF |

| نقش | دسترسی تحلیلی |
|---|---|
| `super-admin` | همه |
| `admin` | همه جز بخش‌های حساس (`users`, `seo`, `security`, `revenue`) |
| `editor` | فقط `analytics.read` |

نکتهٔ مهم: کلاینت هم فقط تب‌های مجاز را می‌سازد تا درخواست بی‌دلیل ۴۰۳ نرود؛ اما
**منبع حقیقت مجوز، سرور است** و هر مسیر مستقل بررسی می‌شود.

### حریم خصوصی

- شمارهٔ تماس و ایمیل کاربران در پنل **پوشانده** می‌شود (`••35`).
- ردیاب مرورگر هرگز شمارهٔ تماس را نمی‌فرستد؛ به‌جایش یک **شبه‌نام یک‌طرفه**
  (FNV-1a) می‌فرستد که برای شمردن کاربر یکتا کافی است و برگشت‌پذیر نیست.
- مسیرهای پنل مدیریت خودشان ردیابی **نمی‌شوند** تا سنجه‌ها آلوده نشوند.
- اگر کاربر `Do-Not-Track` بفرستد، ردیاب اصلاً روشن نمی‌شود.

## ۷. ردیاب ترافیک

`src/services/telemetry/trafficTracker.js` — در `App.jsx` یک‌بار روشن می‌شود.

| ویژگی | جزئیات |
|---|---|
| سشن | در `sessionStorage`، با شکست پس از ۳۰ دقیقه بی‌فعالیتی |
| ارسال | دسته‌ای: هر ۶ ثانیه یا هر ۲۰ رویداد؛ روی `pagehide` با `sendBeacon` |
| Core Web Vitals | `PerformanceObserver` واقعی: LCP، INP، CLS، FCP، TTFB |
| خطا | `window.onerror` و `unhandledrejection` |
| مسیر | از hash خوانده و نرمال می‌شود (شناسه‌های فنی حفظ، کاردینالیتی کنترل) |
| محدودیت نرخ | سرور حداکثر ۵۰ رویداد در هر دسته و ۱۲ درخواست در دقیقه می‌پذیرد |
| بی‌صدایی | همهٔ مسیرها در `try/catch`؛ خطای ردیابی هرگز به کاربر نشان داده نمی‌شود |

رویدادهای پذیرفته‌شده:

```
page_view · session_start · signup · login · logout · article_read · lesson_view
wiki_view · test_start · test_submit · flashcard_review · feature_use · search
cwv · js_error · api_error · purchase
```

فراخوانی از هرجای اپ:

```js
import { track, trackTestSubmit } from '../services/telemetry/trafficTracker';

trackTestSubmit('exam', 82, { meta: { examId: 'x1' } });
track('feature_use', { meta: { feature: 'knowledge-graph' } });
```

| سنجه | شرط | شدت |
|---|---|---|

`ALERT_WEBHOOK_URL` یا `ALERT_TELEGRAM_TOKEN` فعال می‌شوند.

## ۹. خروجی گرفتن

سه قالب، بدون هیچ کتابخانه‌ای:

| قالب | روش |
|---|---|
| CSV | با BOM (تا اکسل فارسی را درست بخواند)؛ هر جدول با یک سرتیتر |

می‌شود، پس هر ۱۶ بخش بدون کد اختصاصی خروجی می‌دهند. نام ستون‌ها به فارسی ترجمه
می‌شود.

## ۱۰. API

```
GET    /api/admin/analytics/sources                 وضعیت اتصال ۱۲ منبع داده
GET    /api/admin/analytics/ping                    پاسخ سبک برای مانیتورینگ بیرونی
GET    /api/admin/analytics/<section>               ?range&from&to
                                                    today|7d|30d|90d|ytd|custom
GET    /api/admin/analytics/export                  ?section&range&from&to
GET    /api/admin/analytics/alerts                  ?range
POST   /api/admin/analytics/alerts
PUT    /api/admin/analytics/alerts/:id
DELETE /api/admin/analytics/alerts/:id
POST   /api/admin/analytics/reset                   پاک‌سازی رویدادها (ابزار عملیاتی)

POST   /api/public/analytics/collect                تلمتری مرورگر (بدون احراز هویت)
```

`<section>` یکی از: `overview` · `traffic` · `users` · `education` · `seo` ·
`performance` · `security` · `revenue` · `products` · `content` · `marketing` ·
`system` · `errors` · `realtime` · `alerts` · `ai`

شکل پاسخ بخش‌ها یکسان است:

```json
{ "success": true, "data": { "section": "traffic", "range": { … }, "data": { … } } }
```

> `POST /api/admin/analytics/reset` عمداً در رابط کاربری نیست. این Endpoint برای
> ابزارهای عملیاتی و تست‌هاست و **تمام رویدادهای واقعی را پاک می‌کند**؛ روی محیط
> پروداکشن با احتیاط استفاده کنید.

۳۳ سنجه — شامل تلمتری عمومی، مجوزدهی هر بخش، حالت «نیازمند اتصال» درآمد، بازرسی

### بررسی سلامت رندر ۱۶ بخش

پیش از تحویل، هر ۱۶ بخش با دادهٔ واقعی موتور تحلیل روی سرور رندر می‌شوند تا خطای
زمان اجرا پیش از رسیدن به مرورگر گرفته شود. این بررسی یک باگ واقعی را گرفت
(`rootCause` شیء بود نه رشته).

```bash
# ۱) یک فایل موقت در ریشهٔ پروژه بسازید که هر ۱۶ بخش را با renderToString رندر کند
# ۲) با esbuild باندل و اجرا کنید (react و react-dom خارج از باندل):
npx esbuild ./__smoke.jsx --loader:.jsx=jsx --loader:.js=js --loader:.css=empty \
  --jsx=automatic --outfile=./__smoke.mjs --bundle --platform=node --format=esm \
  --external:react --external:react-dom --external:react-dom/server --external:react/jsx-runtime
node ./__smoke.mjs
```

> نکتهٔ فنی: باید `--jsx=automatic` بدهید (پروژه از runtime خودکار React 19
> استفاده می‌کند) و خروجی را **داخل پوشهٔ پروژه** بنویسید تا `node` بتواند
> `react-dom` را پیدا کند.

## ۱۲. متغیرهای محیطی

هیچ‌کدام اجباری نیستند. هر متغیری که تنظیم شود، بخش وابسته از حالت «نیازمند اتصال»
به حالت فعال می‌رود. متغیرها **فقط در سرور** خوانده می‌شوند و هرگز به مرورگر
فرستاده نمی‌شوند.

| متغیر | چه چیزی فعال می‌کند |
|---|---|
| `GA_PROPERTY_ID` + `GA_CLIENT_EMAIL` + `GA_PRIVATE_KEY` | Google Analytics 4 |
| `GSC_SITE_URL` (+ همان حساب سرویس) | Search Console: کلیک، نمایش، CTR، رتبه |
| `PAGESPEED_API_KEY` | امتیاز Lighthouse / PageSpeed |
| `PAYMENT_PROVIDER` + `PAYMENT_API_KEY` | درآمد، خرید، AOV، CAC، ROAS |
| `LLM_API_KEY` (+ `LLM_MODEL`) | روایت متنی طبیعی در تحلیلگر |
| `MONITORING_API_URL` + `MONITORING_API_KEY` | سرویس مانیتورینگ بیرونی |
| `ALERT_WEBHOOK_URL` یا `ALERT_TELEGRAM_TOKEN` + `ALERT_TELEGRAM_CHAT` | ارسال هشدار به بیرون پنل |

بخش‌های بدون منبع در نسخهٔ فعلی: **درآمد**، **GeoIP** (موقعیت جغرافیایی)،
**Lighthouse**، **کلمات کلیدی**، **بررسی فنی سئو** (نیازمند Crawl)،
**CAC/ROAS**.

## ۱۳. عیب‌یابی

| نشانه | علت و راه‌حل |
|---|---|
| همهٔ نمودارها خالی‌اند | رویدادی ثبت نشده. سایت را در مرورگر باز کنید تا ردیاب شروع کند، یا `npm run dev` را در یک تب دیگر بالا نگه دارید |
| «لحظه‌ای» همیشه صفر است | `onlineUsers` روی پنجرهٔ ۵ دقیقه حساب می‌شود؛ بدون بازدیدکنندهٔ واقعی صفر است — این درست است |
| سنجه‌های Core Web Vitals خالی‌اند | این‌ها از مرورگر بازدیدکنندگان واقعی می‌آیند؛ با اولین بازدیدها پر می‌شوند |
| بخش درآمد همه‌چیز خالی است | درگاه پرداخت وصل نیست — رفتار عمدی، نه اشکال |
| عدد بخش سئو پایین است | بازرسی واقعی محتوای CMS است؛ عنوان/توضیح متا و لینک داخلی را کامل کنید |
| «مصرف حافظهٔ سرور» بالا نیست ولی سیستم ۹۷٪ است | در macOS حافظهٔ آزاد عمداً کم گزارش می‌شود (Cache). پنل روی مصرف فرایند سرور (RSS) حساب می‌کند، نه کل سیستم |
| خروجی PDF باز نمی‌شود | مسدودکنندهٔ پاپ‌آپ مرورگر را برای این دامنه اجازه دهید |
| پس از `rm -rf database/content` همه‌چیز صفر شد | رویدادها هم پاک شده‌اند؛ دادهٔ CMS از نو seed می‌شود اما تلمتری از صفر شروع می‌کند |
