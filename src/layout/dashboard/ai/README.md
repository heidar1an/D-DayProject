# تپش هوشمند (AI Card + Popup)

دستیار هوشمند تپش — یک کارت مینیمال در بخش «سایر بخش‌ها» که با کلیک، گفت‌وگو را به‌صورت **پاپ‌آپ شناور روی همان صفحه** باز می‌کند. هیچ صفحهٔ مستقل یا Layer جداگانه‌ای وجود ندارد.

```
Caret مینیمال (Idle) → کلیک روی کادر/پیشنهاد → پاپ‌آپ گفت‌وگو → استریم پاسخ
                    ↘ گفت‌وگوی در جریان → نوار «ادامه بده»
```

## فلسفه

- **کارت در داشبورد:** تیتر + یک جمله + چند Chip پیشنهاد + کادر «هر چیزی می‌خواهی بپرس...». ابزارها و شلوغی اینجا نیست.
- **پاپ‌آپ:** با اولین کلیک/فوکوس برای نوشتن، یک پنل شناور (بدون جابه‌جایی صفحه) باز می‌شود: Composer + ابزارها + حالت‌ها + پیوست. کاربر همان‌جا می‌ماند.
- **ادامهٔ گفت‌وگو:** استور مشترک است؛ اگر گفت‌وگویی در جریان باشد، کارت نوار «گفت‌وگوی در جریان — ادامه بده» نشان می‌دهد.

## معماری — یک استور مشترک، چند مصرف‌کننده

```
src/services/ai/
  aiService.js      ← لایهٔ انتزاعی؛ UI نام مدل را نمی‌داند (OpenAI/Claude/Backend تپش)
  mockAI.js         ← پیاده‌سازی Mock با استریم واقعی (تکه‌تکه) + __setFailure برای تست خطا
  mockResponses.js  ← پاسخ‌های نمونهٔ Markdown (جدول، لیست، کد، ترکیب فارسی/انگلیسی)
  aiContext.js      ← Context صفحهٔ فعلی + پیشنهادهای Context-aware

src/layout/dashboard/ai/
  aiStore.js        ← استور ماژول‌سطح مکالمه + ذخیره/بازیابی/حذف گفت‌وگوها + useAIConversation
  AICard.jsx        ← کارت مینیمال داشبورد (Idle / نوار ادامهٔ گفت‌وگو)
  AIPopup.jsx       ← پاپ‌آپ شناور (portal) با مدیریت فوکوس، Esc، پنل ذخیره‌شده‌ها
  AIComposer.jsx    ← ورودی multi-line با auto-grow، Enter/Shift+Enter، ابزارها، حالت‌ها، پیوست
  AIConversation.jsx← لیست پیام‌ها با اسکرول هوشمند (فقط وقتی ته لیست است، دنبال می‌کند)
  AIMessage.jsx     ← پیام کاربر/AI + Markdown + اکشن‌ها + پیشنهادهای ادامه
  aiShared.jsx      ← آیکون‌های SVG سبک + رندرر Markdown بدون وابستگی خارجی
```

**کلید معماری:** استور مکالمه در سطح ماژول است (`aiStore.js`)، نه state کامپوننت. یعنی:

1. با بستن پاپ‌آپ یا جابه‌جایی بین بخش‌های داشبورد، مکالمه از دست نمی‌رود و کارت «ادامه بده» نشان می‌دهد.
2. اگر فردا «صفحهٔ کامل AI» لازم شود، فقط یک مصرف‌کنندهٔ جدید برای همان استور است — نه سیستم سوم.

## ذخیرهٔ گفت‌وگوها

- دکمهٔ «ذخیرهٔ گفت‌وگو» در هدر پاپ‌آپ → کل مکالمه در `localStorage` (کلید `tapesh:ai:conversations:v1`، سقف ۳۰ گفت‌وگو) ذخیره می‌شود.
- ذخیرهٔ دوبارهٔ همان گفت‌وگو، همان رکورد را به‌روز می‌کند (`currentConversationId`) — رکورد تکراری نمی‌سازد.
- «ذخیره‌شده‌ها» فهرست را باز می‌کند: عنوان (اولین پیام کاربر)، تعداد پیام و تاریخ؛ بازیابی با کلیک و حذف با ×.
- گفت‌وگوی بازیابی‌شده کاملاً قابل ادامه است — پیام بعدی به همان تاریخچه اضافه می‌شود.
- ذخیرهٔ تکیِ پاسخ (آیکون Bookmark زیر هر پاسخ AI) جداست: کلید `tapesh:ai:saved-messages`.

## اتصال به Backend (بدون بازنویسی UI)

`aiService.js` فقط سه تابع صادر می‌کند؛ هر Provider جدید همین امضا را دارد:

```js
sendMessage({ text, attachments, mode, context, history, signal, onChunk }) // Promise<fullText>
regenerateResponse({ /* همان امضا */ })
uploadAttachment(file) // Promise<{ id, name, type, size, previewUrl }>
```

- استریم: `onChunk(fullTextSoFar)` هر تکه، **متن تجمیعی کامل** را می‌دهد؛ UI هیچ حالت تجمیعی ندارد.
- توقف تولید: UI فقط `signal` را abort می‌کند؛ متن تا همان لحظه می‌ماند.
- سوییچ Provider: در `aiService.js` مقدار `ACTIVE_PROVIDER` را عوض کن.

## Context-aware (آماده برای بخش‌های دیگر)

هر بخش داشبورد با یک فراخوان به AI می‌گوید کاربر کجاست:

```js
import { setAIContext, clearAIContext } from 'src/services/ai/aiContext';

useEffect(() => {
  setAIContext({ page: 'question-bank', subject: 'physiology', questionId: 'q-41' });
  return clearAIContext;
}, []);
```

پیشنهادهای Context-aware در `aiContext.js` (نقشهٔ `CONTEXT_SUGGESTIONS`) تعریف می‌شوند؛ Chipهای کارت و درخواست چت از آن تغذیه می‌کنند. Personalization فیلد `user` در همان Context است؛ فعلاً خالی و آمادهٔ پر شدن از `userData`.

## قراردادهای UI

- **باز شدن:** کلیک روی کادر کارت یا هر Chip → پاپ‌آپ؛ فوکوس مستقیم روی Composer. Chip متنش را در Composer می‌گذارد.
- **کیبورد:** Enter ارسال، Shift+Enter خط جدید، Esc بستن پاپ‌اور ابزار/حالت و بعد Esc دوم بستن پاپ‌آپ؛ Tab داخل دیالوگ می‌چرخد (focus trap).
- **بستن:** کلیک روی backdrop، دکمهٔ × یا Esc — فوکوس به کارت برمی‌گردد و اسکرول بدنه آزاد می‌شود.
- **حالت‌ها:** عمومی / مطالعه / پزشکی / تست — Placeholder و درخواست ارسالی را عوض می‌کنند.
- **ابزارها:** ۳ ابزار پرکاربرد در Toolbar؛ بقیه پشت «ابزارها+». کلیک روی ابزار، قالب متن را در Composer می‌گذارد.
- **اکشن‌های پیام:** کپی، تولید دوباره، پسند/نپسند، هم‌رسانی (Web Share با fallback به کپی)، ذخیره + پیشنهادهای ادامه.
- **خطا:** `__mockAI.__setFailure(true)` از کنسول → Error State آرام با «دوباره تلاش کن».
- **حد ورودی:** ۴۰۰۰ کاراکتر؛ شمارنده بعد از ۹۰٪ ظاهر می‌شود.

## عملکرد و دسترس‌پذیری

- کل کارت و پاپ‌آپ با `React.lazy` بارگذاری می‌شوند (chunk جدا ~۱۲KB gzip) و تا ورود به «سایر بخش‌ها» دانلود نمی‌شوند.
- پاپ‌آپ با `createPortal` در `document.body` رندر می‌شود؛ `role="dialog" aria-modal="true"`، قفل اسکرول پشت، فوکوس اولیه و بازگشت فوکوس.
- رندرر Markdown خودنویس است: فقط React Element می‌سازد، هیچ HTML خامی تزریق نمی‌کند.
- `role="log" aria-live="polite"` برای مکالمه، `aria-pressed` برای بازخوردها، فوکوس‌رینگ یکدست بنفش.
- انیمیشن‌ها opacity/transform محض + گارد `prefers-reduced-motion`.
- موبایل: پاپ‌آپ به‌صورت Bottom Sheet تمام‌عرض با `92dvh`؛ Toolbar ابزارها اسکرول افقی.

## محدودیت‌های فعلی (عمدی)

- پاسخ‌ها Mock هستند و از کلیدواژهٔ پیام انتخاب می‌شوند (`pickResponse`).
- «به فلش‌کارت تبدیل کن» و «از این پاسخ تست بساز» فعلاً یک prompt به همان گفت‌وگو می‌فرستند؛ اتصال به موتور فلش‌کارت/بانک تست آینده است.
- فهرست ذخیره‌شده‌ها state محلی پنل است؛ بعد از حذف/بازیابی خودش تازه‌سازی می‌شود و sync سراسری لازم ندارد.
