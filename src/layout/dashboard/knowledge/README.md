# شبکهٔ دانش تپش — معماری

لایهٔ Knowledge Graph تپش: دانش پزشکی بر اساس **ارتباط میان مفاهیم**، نه درس و فصل.
مرکز شبکهٔ نمونه «دیابت» است و ۵۶ مفهوم از ۸ درس به آن وصل‌اند (۸۸ رابطهٔ تایپ‌دار).

## نقشهٔ فایل‌ها

```

│                            (فقط داده؛ قرارداد شکل نود/یال سر فایل مستند است)
├── graphModel.js         ← موتور خالص بدون state: adjacency، N-Hop، مسیر BFS،
```

## ۱. مدل داده

`Topic (نود)` · `Relationship (یال تایپ‌دار)` · `Course` · `NodeType` ·
`UserProgress` — شکل دقیق هر موجودیت در `graphData.js` مستند شده و همان
قرارداد Backend آینده است.

- یال جهت‌دار است: `source —type→ target`؛ ۱۵ نوع رابطه با برچسب فارسی
  (`produces`، `regulates`، `causes`، `treated_by`، …).
- هر نود `prerequisites[]` دارد — منبع ساخت «مسیر مطالعه» (نه فهرست فصل کتاب).
- یک مفهوم می‌تواند `courses[]` چندتایی داشته باشد؛ همین «پل‌های بین‌درسی»
  منطق اصلی feature است (دیابت هم فیزیولوژی است هم پاتولوژی هم بیوشیمی).

## ۲. API Contract (قرارداد با Backend)

- `GET /knowledge/graph` — نودها، یال‌ها، layout، آمار
- `GET /knowledge/nodes/:id` — جزئیات + همسایه‌های برچسب‌دار + پیش‌نیاز/وابسته
- `GET /knowledge/nodes/:id/content` — شمارش محتوای مرتبط
- `GET /knowledge/path?from=&to=` — کوتاه‌ترین مسیر مفهومی
- `GET /knowledge/learning-path/:nodeId` — توالی مطالعه
- `GET /knowledge/progress` و `PUT /knowledge/progress/:nodeId`

اتصال واقعی فقط بدنهٔ توابع `knowledgeService.js` را تغییر می‌دهد؛ UI دست نمی‌خورد.
چیدمان گراف هم می‌تواند از سرور بیاید (فیلد `layout` در خروجی graph).

## ۳. محتوای مرتبط — پویا، نه Hard-Code

شمارش «۱۲ درسنامه / ۸۴ تست / …» از لایهٔ دادهٔ سایر بخش‌های تپش شمرده می‌شود
(ویکی، بانک تست، فلش‌کارت، مقالات) با تطبیق کلیدواژهٔ نرمال‌شدهٔ هر مفهوم.
هرچه آن بخش‌ها بزرگ‌تر شوند این عددها واقعی‌تر می‌شوند؛ هر اتصال در try/catch است
تا خرابی یک سرویس فقط شمارش صفر باشد، نه شکست شبکهٔ دانش. در نسخهٔ بک‌اند همین
تطبیق به سرچ ایندکس/PG_vector منتقل می‌شود و خروجی همین شکل می‌ماند.

## ۴. وضعیت یادگیری کاربر

۶ وضعیت: `unstarted / studying / studied / mastered / review-needed / weak` +
درصد پیشرفت — در `localStorage` با کلید `tapesh:knowledge:v1:<userId>`.
وضعیت در گراف با نقطهٔ رنگی ظریف روی نود نشان داده می‌شود (ضعیف قرمز، مسلط بنفش…).
پیشرفت کلی با `overallMastery()` وزن‌دهی می‌شود. اتصال آینده به ProgressService
درسنامهٔ جامع (`learningBridge`) آماده است.

## ۵. تعامل با گراف

- Hover نود → هایلایت خود + همسایه‌ها؛ Hover یال → برچسب فارسی رابطه
- Click → انتخاب + پنل جزئیات؛ Double-Click → ورود به صفحهٔ موضوع
- درگ نود جابه‌جایی دائمی، درگ پس‌زمینه pan، چرخ/پینچ زوم روی نشانگر
- Progressive Disclosure: پیش‌فرض فقط مفاهیم اصلی (اهمیت ≥۴)؛ «نمایش شاخه‌ها»
  همسایه‌های نود انتخابی را با عمق انتخابی (۱-۳ هاپ) اضافه می‌کند
- فیلتر درس نودهای بی‌ارتباط را کم‌رنگ می‌کند نه حذف — ارتباط بین درس‌ها حفظ می‌شود

## ۶. توسعه‌های آینده (مسیر آماده)

AI-generated connections (یال جدید = رکورد جدید)، Weakness Detection (وضعیت weak
از بانک تست به progressMap تزریق می‌شود)، Semantic Search (جایگزینی searchNodes
با endpoint)، AI Tutor روی گراف، Spaced Repetition مبتنی بر Connection‌ها.
هیچ‌کدام نیاز به تغییر UI ندارد — فقط سرویس و داده.
