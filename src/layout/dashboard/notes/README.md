# یادداشت تپش — معماری

دفترچهٔ یادداشت شخصی: دانشجو نکته‌ها، ترفندها و برنامه‌هایش را با موضوع، تگ، رنگ و
اتصال به منبع نگه می‌دارد؛ چک‌لیست‌ها پیشرفت جمع‌بندی را نشان می‌دهند.

## نقشهٔ فایل‌ها

```
src/services/notes/
├── mockData.js        ← موجودیت Note + SUBJECTS (همان لیست ویکی) + NOTE_COLORS + SOURCE_TYPES + seed
└── notesService.js    ← قرارداد API واقعی (فعلاً Mock + localStorage) + فیلتر/مرتب‌سازی/snippet

src/layout/dashboard/notes/
├── NotesSection.jsx   ← پوسته: نوار بالا (بازگشت + ساخت یادداشت) + هیرو + جست‌وجو/مرتب‌سازی
│                        + بخش واحد «موضوع و تگ» + گلچین/همهٔ یادداشت‌ها
├── NoteDetail.jsx     ← نمای کامل یادداشت: چک‌لیست تعاملی، منبع، تگ‌ها، متا
├── NoteEditor.jsx     ← مودال ساخت/ویرایش (متنی | چک‌لیست + موضوع + تگ + رنگ + منبع)
│                        + یک کادر خلاصهٔ تپش هوشمند برای کل پیش‌نویس
├── notesShared.jsx    ← آیکون‌ها، Modal، SubjectChip/KindBadge، DeleteButton دومرحله‌ای
├── notes.css          ← چیپ‌ها + انیمیشن‌های ورود + گارد prefers-reduced-motion
└── README.md
```

## ۱. مدل داده

- **Note** `{ id, userId, title, kind: 'text'|'checklist', body, items[{id,text,done}], subjectId, tags[], color, pinned, source: {sourceType, title} | null, createdAt, updatedAt }`
  - `kind='checklist'` → محتوا در `items` است و `body` خالی.
  - `source` پایهٔ «ساخت یادداشت از درسنامه/تست/مقاله/ویکی» در نسخه‌های بعدی است؛
    پنل‌های درسنامه/تست بعداً فقط `createNote(userData, { source: … })` را صدا می‌زنند.
- **SUBJECTS** دقیقاً همان لیست ویکی تپش است (id + label + accent) + `general` —
  تا بعداً رنگ موضوع در کل اکوسیستم یکی بماند.

## ۲. اصول سرویس

- منطق نمایشی (snippet، فیلتر، مرتب‌سازی، پیشرفت چک‌لیست) در سرویس است؛ UI فقط رندر می‌کند.
- جست‌وجو با نرمال‌سازی فارسی (ی/ي، ک/ك، نیم‌فاصله) روی عنوان/بدنه/تگ‌ها/آیتم‌ها/منبع.
- مرتب‌سازی: `updated | created | title`؛ **پین‌شده‌ها همیشه جلوتر**.
- toggle آیتم چک‌لیست `updatedAt` را بالا نمی‌برد (تیک‌زدن ویرایش محسوب نمی‌شود).
- seed فقط بار اولِ هر کاربر ساخته می‌شود؛ تاریخ‌ها نسبت به زمانِ اولین ورود واقعی‌اند.

## ۳. تجربهٔ کاربری

- ورود از اکشن‌کارت «یادداشت‌ها» صفحهٔ خانه (`DashboardActionCards`) — مثل فلش‌کارت
  عمداً در ناوبری هدر نیست. مسیر: `handleSectionChange('notes')` → `sections.notes`.
- نوار بالای لایه (`LayerTopbar`) همان چیدمان نوار فلش‌کارت است: «بازگشت به داشبورد» در
  ابتدای ردیف و دکمهٔ **ساخت یادداشت** در انتهای ردیف. مسیر متنی («داشبورد / یادداشت‌ها»)
  عمداً برداشته شده؛ فاصلهٔ انتهای ردیف را `margin-inline-start: auto` خودِ دکمه می‌گیرد.
  دکمهٔ ساخت عمداً در هیرو نیست؛ `onBack` از `DashboardLayout` می‌آید.
- هیرو فقط تیتر و توضیح است: نه هالهٔ نور پشت تیتر، نه ردیف آماری. تیتر با قهوه‌ای پالت
  (`--brown-ink`) رنگ می‌گیرد تا در تم روشن هم خوانا بماند.
- **اعداد آماری کنار بخش خودشان‌اند، نه در یک ردیف جدا:** «یادداشت» = شمارندهٔ سرتیتر
  «همهٔ یادداشت‌ها» (تعداد کارت همان بخش)، «گلچین‌شده» = شمارندهٔ سرتیتر «گلچین‌شده‌ها»،
  «موضوع» = نشان کنار ردیف فیلتر موضوع، «این هفته» = نشان کنار نوار جست‌وجو.
  پس جمع دو شمارندهٔ سرتیتر = کل یادداشت‌ها.
- **موضوع و تگ یک ردیف چیپ‌اند** (`TopicChips`) و ظاهرشان آینهٔ چیپ مسیرهای «بانک تست
  علوم پایه» است (`PathChip` در `tests/bank/BankHome.jsx`): یک ردیف افقی وسط‌چین با اسکرول
  افقی و اسکرول‌بار پنهان، هر چیپ فقط آیکون + عنوان. کادر و ردیف‌بندی برداشته شده‌اند.
  **تگ‌ها دسته‌بندی ندارند** (`TAG_GROUPS`/`CUSTOM_TAG_GROUP`/`groupTags` حذف شدند) و تخت
  می‌آیند؛ رنگ هر تگ از خودِ متن تگ می‌آید: `tagAccent(tag)` با هش FNV-1a یک رنگ از
  `TAG_COLORS` (همان پالت تپش) برمی‌گرداند ⇒ هر تگ رنگ تصادفیِ خودش را دارد و همان تگ
  همیشه همان رنگ را می‌گیرد (پایدار بین چیپ فیلتر، کارت فهرست، نمای کامل و ویرایشگر).
  `.nt-chip` عمداً همان مقادیر محاسبه‌شدهٔ `PathChip` را دارد (ارتفاع ۴۲، `padding: 10px 16px`،
  `font-size: 13px`، `gap: 8px`، حاشیهٔ ۸٪، پس‌زمینهٔ `--surface`)؛ تنها تفاوت این است که
  آنجا چیپ ناوبری است و اینجا فیلتر، پس حالت `aria-pressed` دارد.
- ترتیب چیپ‌ها: «همه» (پاک‌کردن فیلتر موضوع و تگ، بدون دست‌زدن به عبارت جست‌وجو) ← نشان
  «N موضوع» ← چیپ درس‌ها ← چیپ تگ‌ها (پرکاربردترین اول، `collectTags`). کلیک روی چیپ فعال،
  فیلتر را برمی‌دارد.
- **ورود پله‌ای کارت‌ها با جابه‌جایی موضوع:** گرید هر بخش کلیدش `subjectFilter|tagFilter` است،
  پس با هر تغییر موضوع یا تگ از نو mount می‌شود و انیمیشن `dash-stagger` (همان انیمیشن
  بلوک‌های داشبورد) دوباره اجرا می‌شود — کارت‌ها یکی‌یکی بالا می‌آیند. جست‌وجو و مرتب‌سازی
  عمداً در کلید نیستند تا تایپ کردن هر حرف، گرید را دوباره از نو نسازد.
- **تپش هوشمند در ویرایشگر یک نقطهٔ ورود دارد:** یک کادر خلاصه در بالای فرم با یک آیکون
  «عصا» و چهار کنش که کل پیش‌نویس (بدنه، آیتم‌ها، پرسش/پاسخ‌ها، سلول‌های جدول) را یک‌جا
  بازنویسی می‌کند. آیکون‌های تک‌تک کنار هر فیلد برداشته شدند. در نمای یادداشت هم همان
  الگو هست: یک دکمهٔ «تپش هوشمند» در نوار بالا که پنل کنش‌ها را باز می‌کند.
- کارت‌ها: نوار رنگ موضوع/کارت در لبهٔ شروع (RTL)، پیش‌نمایش، نوار پیشرفت چک‌لیست،
  تگ‌ها (حداکثر ۳ + «+n»)، اکشن‌های pin/ویرایش/حذف.
- حذف دومرحله‌ای: کلیک اول «مطمئنی؟»، کلیک دوم حذف؛ ۳ ثانیه بعد دکمه ریست می‌شود.
- Escape: در نمای یادداشت → بازگشت به فهرست؛ در مودال → بستن مودال (دو مسیر مستقل‌اند
  و Escape وقتی مودال باز است از نمای یادداشت عبور نمی‌کند).

## ۴. اپتیمستیک + Offline-ready

- هر تغییر اول `setNotes` محلی را عوض می‌کند و بعد سرویس در پس‌زمینه می‌رود؛
  در پایان `silentRefresh` دادهٔ واقعی را بدون روشن‌کردن اسکلت برمی‌گرداند.
  نتیجه: هیچ mutation لایه‌بندی (Layout Shift) ندارد.
- در نسخهٔ سرور همان توابع به fetch تبدیل می‌شوند؛ صف Sync مثل فلش‌کارت قابل افزودن است.

## ۵. API Contract (قرارداد با Backend)

- `GET    /api/notes?q=&subject=&sort=`
- `POST   /api/notes`
- `PATCH  /api/notes/:id`
- `DELETE /api/notes/:id`
- `POST   /api/notes/:id/pin`
- `POST   /api/notes/:id/checklist/:itemId/toggle`

اتصال واقعی فقط بدنهٔ توابع `notesService.js` عوض می‌شود؛ UI دست نمی‌خورد.

## ۶. پایداری و دسترس‌پذیری

- داده در `localStorage` با کلید `tapesh:notes:v2` به تفکیک `userId`
  (`u:<id>`، مهمان: `u:guest`). **هیچ یادداشت پیش‌فرضی seed نمی‌شود** — فضای هر کاربر خالی
  شروع می‌شود. کلید نسخهٔ قبل (`tapesh:notes:v1` که یادداشت‌های نمونهٔ نمونه در آن بود)
  در نخستین خواندن خودکار پاک می‌شود. ریست کامل: `localStorage.removeItem('tapesh:notes:v2')`.
- تست حالت خطا از کنسول: `__notesService.__setFailure(true)` و تعویض بخش.
- `dir=rtl`، اعداد فارسی (`toFa` از leagueShared)، `aria-pressed` برای pin/تیک،
  `role=radiogroup/radio/progressbar/dialog`، گارد `prefers-reduced-motion`.
- تنها استثنای گاردِ کاهش حرکت، ورود پله‌ای کارت‌هاست: آن انیمیشن از `dash-stagger`
  می‌آید و مثل بقیهٔ لایه‌های داشبورد گارد نمی‌شود؛ پس `.nt-card` عمداً در فهرست
  `animation: none` نیست (خودش انیمیشن مستقلی ندارد که باید خفه شود).
